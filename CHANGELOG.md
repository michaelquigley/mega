# CHANGELOG

## Unreleased

CHANGE: **The binary, the module path and the default config and workspace paths have changed.** (2026-11-11) roundhouse is now mega, spoken of as "metawoo mega". The binary is `mega`, the module is `github.com/michaelquigley/mega`, the configuration is `~/.config/mega/mega.yaml`, and the workspace is `~/.local/share/mega`. The port is unchanged. The page's title is "metawoo mega", and its own wording says mega. The UI's per-browser preferences (panel width, collapsed panel, folded projects, reply box height) start fresh once. While a workspace still sits in `~/.local/share/roundhouse` and the new one does not exist, `mega` refuses to start rather than open an empty workspace beside it, and points at `docs/future/mega-cutover.md`, which moves it. Entries above this line and the journals keep the old name as written.

FIX: After sending a prompt, its last line no longer hides under the input panel until the agent's first output. The activity line appearing as the turn starts made the panel one line taller, and nothing re-pinned the view. Now, while the view follows the bottom, any change in the panel's height keeps the newest content above it: the activity line, a docked request arriving or leaving, the reply box growing. A view you have scrolled up is not moved.

FEATURE: **A conversation shows its MCP servers.** (2026-11-12) The conversation's header sums up the MCP servers its harness has connected, such as "3 MCP servers, 1 needs sign-in, 1 failed", on the notice tone while any is not connected. Pressing it lists each server with its status and any error, and its tools on expansion; Codex gives each tool a description, and Claude Code 2.1.318 gives none. A server that needs signing in says where: `/mcp` in Claude Code in a terminal, or `codex mcp login <name>`. mega starts no sign-in and changes no server. The servers are read from the running harness, kept in memory, and gone when the runtime is released; a conversation with no runtime says it is not running. A failed server is never attention: it does not put a conversation in the needs-you list. The list follows changes as each harness can report them. Claude announces none, so mega asks as the runtime starts, while a server is still connecting, and when a turn reports other statuses. Codex announces each server's startup, and is asked again at each turn's start.

CHANGE: **Next waiting is Ctrl+/ only, and Ctrl+' shows and hides the side panel.** (2026-11-12) The bare `n` shortcut is gone, and the needs-you hint reads "Ctrl+/". Ctrl+' switches between the side panel and the rail, from anywhere, the reply box included, and the collapse and expand controls name it. Both need Ctrl, so neither takes a keystroke that would type.

CHANGE: **Starred projects start unfolded, and the rest start folded.** (2026-11-12) Your own fold or unfold of a project wins and is kept in this browser, so starring or unstarring changes how a project shows only while you have made no choice for it. Projects you had folded stay folded. Opening a conversation still unfolds its project, without recording a choice.

CHANGE: **The conversation sits in the middle of its pane.** (2026-11-12) Its 960-pixel column is centred, with its header, history, requests, input panel and the banners that span it, and re-centres when the side panel collapses to the rail. The project page and the connecting and unreachable views are centred the same way.

CHANGE: **Your own prompts no longer carry the "You" label.** (2026-11-12) The block's tint already says whose they are. A prompt from outside mega is labelled "outside mega", and an imported reply keeps "From outside mega".

CHANGE: **The side panel shows mega's version, and says when a newer mega is running.** (2026-11-12) The version sits beside the connection status, and on the rail as a title. Either opens what `mega version` prints, with the log file's path and the Claude Agent SDK version the shim runs, from the new read-only `GET /api/version`. After a rebuild and restart, an open page that still runs the previous interface says "A newer mega is running; reload this page" where the connection status is. It never reloads itself.

FIX: A page could go blank while mega shut down. Once an orderly stop lets go of each conversation's live state, the service still answers the page that asked for the shutdown, and a workspace read in that moment gave every conversation an empty attention. Another open page that read it went blank when it lost the service a moment later. A read in that moment is now computed from the facts as they stood when the service let go of them, so a runtime that had ended in an error still shows the error. The rebuilt shutdown check found it, about one run in twenty.

CHANGE: **The browser checks run as a suite.** (2026-11-12) `make checks` builds mega and runs every browser check in `checks/` against the fake Claude shim and the fake Codex, each on its own scratch mega, and reports each suite's steps, failures and time; `make checks SUITE=<name>` runs one. Playwright is now a pinned development dependency, `make checks-browser` installs its browser once, and a missing browser is reported as a failure, never skipped. The checks lost with `/tmp` on 2026-11-12 are rebuilt for three surfaces: requests, the input panel and the shutdown gate. A long-conversation check is kept as the start of the conversation view's suite. Each check's projects point Claude at scratch settings, and no check reads your own Claude settings or shell start-up files. `make test` is unchanged and never starts a browser. The UI's lint toolchain moves to ESLint 10, with `minimatch` pinned to a patched release, and Vite and its React plugin take their waiting updates, so a clean `npm ci` in `ui/` prints no deprecation warning and reports no vulnerabilities.

FIX: An approved project environment could still let a file in the repository decide which programs mega itself runs. Approving `.mega/environment.yaml` approves its text, but an activation such as `devprj` reads other files in the checkout, which an agent can usually write. A PATH it put first could have made mega's own `node` or `git` a program from the checkout. Four changes:
- mega now finds its own programs (`node`, `git`, the harness binaries and a script's `#!/usr/bin/env` interpreter) on the PATH from before the activation, and runs them by absolute path, while agents still get the whole activated environment.
- An approval records the names of the variables the activation changed. A later start that finds it changing a different set is refused with its own code until you approve again, with the added and removed names shown on the project page.
- Approvals are bound to the file's full SHA-256 digest instead of its first 16 hex digits. Approvals made before this need approving once more, and the page says so.
- The environment resolves through a login and interactive shell, so tools set up in profile scripts (`/etc/profile.d`, `~/.profile`) are present.

FIX: Every agent in every project ran in the environment mega was started in, not its project's. With Go projects isolated by `devprj`, an agent's `make clean` in one project cleared another project's Go bin, and a project's own bin was not on `PATH`. Each project now runs in its own shell environment: your interactive shell, started in the checkout from a clean base, with the project's activation applied, at each runtime start and for mega's own helpers (history, discovery, the model list, path search). The activation lives in the repository as `.mega/environment.yaml` (`activate: devprj`, for example). mega runs it only after you approve it on the project page, and refuses to start anything there when it changes until you approve the new version, shown beside the old. A local override can ignore the file or use another activation. A failed, timed-out or malformed activation refuses launch, prompt and Start with its own code and says why. Each runtime start records its environment's changed names and a fingerprint, never values, and the conversation header says when an agent is running in an older environment than its project's. The harness preflight now checks each project's environment.

FIX: Opening or switching to a long conversation no longer costs its whole history. The page now reads the newest ten turns and the turn in flight, each turn whole from its first event. Show earlier, above the history, loads the ten turns before, and Show all loads the rest; either keeps the view where it was, and the bar says how much lies earlier. Native events are no longer sent unless the native events toggle asks for them; turning it on refetches what is shown with them. The service keeps an index of each log in memory, so a read seeks instead of parsing the log from its top. On a generated 20,000-event, 55 MB conversation, a read with nothing new went from 406 ms to 1 ms, opening from 882 ms and 58 MB to 16 ms and 0.34 MB, first content on a fresh page from 2.3 s to 0.2 s, and a switch between two such conversations from 2.1 s to 0.06 s. The reading position follows the newest event the page has been given, so it needs no earlier history, and a native event the page was not sent is no gap. The service now logs any request that takes longer than a second, with its path, duration and size. The page's connecting and loading states say what they wait for: the request, for how long, the attempt and the last error.

CHANGE: mega has a tagline, "build your constellation" (provisional), in place of "a workspace for a gang of coding agents". It is the root command's help, the launcher's comment and the README's opening. The page's title is now "mega", with the needs-you count and the shutdown state prefixing it as before ("(2) mega", "Ready to shut down · mega"), and the shutdown notification is titled "mega". "metawoo mega" appears only in the README's first sentence. Run `mega desktop integrate` again to update an installed launcher's comment.

FIX: mega started from the desktop launcher now has your shell's environment. The launcher used to start mega with the desktop session's bare `PATH`, so Claude conversations failed with "node: executable file not found" and an "internal error". Every agent would have run without your toolchain. `mega desktop integrate` now writes a launcher that starts mega through your interactive shell (bash, zsh or fish), and prints the line it wrote and why; `--plain` keeps the old form. Run `mega desktop integrate` again to update an existing launcher. mega also checks whether each agent's executable can be found: a harness that cannot run is marked in the new-conversation dialog, with mega's `PATH`, and new work for it is refused with the name of what is missing, never "internal error". The `PATH` mega started with is logged at start-up.

FEATURE: mega can live in the system tray. `mega daemon` runs the same service under a tray icon whose menu opens mega in your browser, and arms or cancels "shut down when idle". Quit goes through the shutdown gate: with nothing in flight it stops cleanly, every agent released; with anything running it arms the gate and opens the page instead, so a stray click never interrupts an agent. The icon turns gold, with a count in its tooltip, while something needs you. `mega desktop integrate` installs a launcher that starts the daemon, with its icons, and `mega desktop remove` takes it away again; nothing starts at login. Started with no terminal, mega logs to `~/.local/state/mega/mega.log`, which `mega version` names; a log past 10 MB is set aside as `mega.log.1` at the next start. Launching mega from the desktop while it is already running opens the running one's page. A second `mega serve` on the same port or workspace says another mega is running, and where. `mega serve` is unchanged and stays the default.

CHANGE: mega has a mark: the hub, a gold centre with five light points around it on the dark tone, as the browser tab's icon. When something needs you, the tab says so: the mark turns gold with dark points, and the title gains the count, "(2) metawoo mega". "Ready to shut down" still takes the title while the shutdown gate offers it. While the page has lost the service, the tab shows the plain mark, since it cannot say what is waiting. PNG renderings of both states are in `cmd/mega/` for the tray and desktop icons to come.

FIX: A project whose checkout has moved, been removed or was set to the wrong path now says so, instead of looking normal until an agent fails to start there with that agent's own error. Its page names the path and the reason (does not exist, not a directory, not readable), the tree and the collapsed rail mark it, and new conversations, adoptions, prompts and Start are refused with "the checkout is missing" and the path. Everything else keeps working, so you can put the checkout back or remove the project. Put it back and the notice goes at the next read.

FEATURE: `roundhouse` serves a localhost workspace on `127.0.0.1:8470` where projects are registered from existing checkouts, listed, renamed, and removed without touching the checkout. The list survives a restart, a change reaches the disk before any browser is shown it, a second instance on the same port or the same data directory refuses to start, and a project whose checkout Claude has not been trusted in shows a notice rather than having its trust flag set on the operator's behalf.

FEATURE: Claude Code conversations run inside a project: launch one with an opening prompt, reply, answer its approvals and questions from any open browser (the first answer wins and a late one is refused), interrupt it, release it to continue in a terminal with the exact `claude --resume` command shown, and resume it to pick up what happened there. Native permissions are inherited, never relaxed. A conversation always resumes its own session by id, and history from the terminal is added without repeating what is already shown. After a service restart, a conversation whose runtime was not seen to stop is marked as lost supervision until it is deliberately resumed, and any request that was pending is shown as lost rather than answerable.

Approvals and Codex's questions arrive as cards, and an answer to a question goes straight into the turn that is waiting for it. Release shows the exact `codex resume` command, and if a command Codex started is still running after release, the conversation says so with its process ids instead of claiming a clean stop.

FEATURE: Sessions started outside Roundhouse can be adopted. Pick a Claude or Codex session stored for the project's checkout from a list of those no conversation holds yet, and its history comes in with it; the first prompt continues that exact session.

FEATURE: The workspace shows which conversations need you. A list at the top of the sidebar holds every conversation with a pending question or approval, then every one with unread output from a finished turn, each in the order it started waiting; Ctrl+/, or a bare n outside a text field, walks it. Every conversation in the project tree carries a mark for what it is doing: waiting for an answer, unread, working, ended in an error, idle, or uncertain after a restart. Opening a conversation marks what is on screen as read but never answers or hides a request. FEATURE: A conversation can be removed from the workspace from its header, once its runtime is released. The confirm says what stays: the checkout and the agent's own session, which can be adopted again from the project. What goes is Roundhouse's own history and reading position for it. If the conversation was open, its project opens in its place, in every browser. Removing a project now works the same way for all its conversations: it waits until none of them has a runtime, including one whose supervision was lost in a restart, and it deletes Roundhouse's history and reading positions for them instead of leaving them on disk.

CHANGE: A conversation opens at its latest activity, with any waiting question or approval in view, instead of at the top of its history, and never keeps the scroll position of the conversation shown before. FEATURE: Conversations render markdown. Code blocks show their language and have a Copy button. FIX: Long messages are no longer cut off. Replies, prompts and tool output past about 4000 characters used to end mid-sentence with an ellipsis, and Copy on a code block in them copied only what was shown. They are now kept and shown whole. Long code blocks open at their first 40 lines with a "Show all" button, and Copy always takes the whole block. Messages recorded before this fix stay as they were recorded.

FEATURE: Claude conversations run in the permission mode you choose, as in the terminal: default, auto (a classifier approves routine calls and only the rest is asked), accept edits, or plan. Pick it when launching. Change it from the conversation header while it runs; the change applies from the next tool call, shows in the history, and leaves any waiting approval in place. The choice sticks across release and resume, and a terminal visit never changes it. With no choice, Roundhouse uses the manual default mode, unless your Claude settings name a default mode, which is then inherited and marked as such. Approvals that still arrive in auto mode say the classifier could not decide them. Bypass modes are never offered.

FIX: When Claude refuses a permission mode switch, the conversation's stored choice now goes back to what it was before, including no choice at all, so a conversation that inherited its mode from your settings keeps inheriting. Roundhouse also reads your Claude settings the way Claude does for a checkout below its repository root: a default mode in the repository root's `settings.local.json` is inherited, the root's shared `settings.json` is not, and `auto` or bypass named in a project file is ignored, as Claude ignores it. Two error messages about permission modes now quote the names they mention.

CHANGE: A stopped Claude conversation's permission mode can be set from its header ahead of the next prompt, for example to auto after a restart. The choice is stored, shown as "next launch: X", and passed when the conversation next starts. The control shows for every Claude conversation except one whose supervision was lost.

FIX: Codex conversations can use MCP tools. It now arrives as an approval card naming the server and the tool, with what the tool does and the parameters it would be called with: Allow runs it, Deny stops it, and where Codex offers it, "Allow this tool for the session" stops it asking again for that tool in that conversation. Roundhouse never chooses "always", which would change your Codex configuration. A form an MCP server asks you to fill in (choices, text, numbers, yes or no) appears as a question card. Kinds Roundhouse cannot answer yet are recorded saying what was asked, and interrupting still gets you out.

FEATURE: Conversations run on the model and effort level you choose, for Claude and Codex alike. A running conversation can change both from its header: Claude switches from its next response, Codex from your next prompt, and with no runtime the change waits for the next launch. The header shows the model as the harness reports it, the effort as Codex reports it or, for Claude, which never reports it, the level asked for, marked "(requested)", and "next prompt: …" for a change not yet in effect.

CHANGE: You can see at a glance what is working. A working conversation's mark is a turning arc, and the marks are a little larger. Nothing moves that is not live: with reduced motion set, or while the page has lost its connection and shows only what it last knew, the marks hold still and the times stop.

CHANGE: A conversation reads as blocks. The agent's replies sit on a slightly different tone from the page, as your prompts already did on theirs, with code inside a reply set into it. A reply still arriving already wears its block, so nothing jumps when it lands.
