# CHANGELOG

## Unreleased

FEATURE: `roundhouse` serves a localhost workspace on `127.0.0.1:8470` where projects are registered from existing checkouts, listed, renamed, and removed without touching the checkout. The list survives a restart, a change reaches the disk before any browser is shown it, a second instance on the same port or the same data directory refuses to start, and a project whose checkout Claude has not been trusted in shows a notice rather than having its trust flag set on the operator's behalf.

FEATURE: Claude Code conversations run inside a project: launch one with an opening prompt, reply, answer its approvals and questions from any open browser (the first answer wins and a late one is refused), interrupt it, release it to continue in a terminal with the exact `claude --resume` command shown, and resume it to pick up what happened there. Native permissions are inherited, never relaxed. A conversation always resumes its own session by id, and history from the terminal is added without repeating what is already shown. After a service restart, a conversation whose runtime was not seen to stop is marked as lost supervision until it is deliberately resumed, and any request that was pending is shown as lost rather than answerable.

FEATURE: Codex conversations run alongside Claude ones. Each gets its own private Codex server and inherits your approval policy and sandbox. Approvals and Codex's questions arrive as cards, and an answer to a question goes straight into the turn that is waiting for it. Release shows the exact `codex resume` command, and if a command Codex started is still running after release, the conversation says so with its process ids instead of claiming a clean stop.

FEATURE: Sessions started outside Roundhouse can be adopted. Pick a Claude or Codex session stored for the project's checkout from a list of those no conversation holds yet, and its history comes in with it; the first prompt continues that exact session.

CHANGE: Messages imported from a harness's own history are labeled as from outside Roundhouse rather than from the terminal, since adopted history can come from anywhere.

FEATURE: The workspace shows which conversations need you. A list at the top of the sidebar holds every conversation with a pending question or approval, then every one with unread output from a finished turn, each in the order it started waiting; Ctrl+/, or a bare n outside a text field, walks it. Every conversation in the project tree carries a mark for what it is doing: waiting for an answer, unread, working, ended in an error, idle, or uncertain after a restart. Opening a conversation marks what is on screen as read but never answers or hides a request. Releasing a conversation, restarting the service, or picking up a terminal visit does not make anything unread on its own.

FEATURE: A conversation can be removed from the workspace from its header, once its runtime is released. The confirm says what stays: the checkout and the agent's own session, which can be adopted again from the project. What goes is Roundhouse's own history and reading position for it. If the conversation was open, its project opens in its place, in every browser. Removing a project now works the same way for all its conversations: it waits until none of them has a runtime, including one whose supervision was lost in a restart, and it deletes Roundhouse's history and reading positions for them instead of leaving them on disk.

CHANGE: A conversation opens at its latest activity, with any waiting question or approval in view, instead of at the top of its history, and never keeps the scroll position of the conversation shown before. New output is followed only while you are at the bottom; if you have scrolled up to re-read, the view stays put and a "Newer activity below" button takes you back.

FEATURE: Conversations render markdown. Replies, your own prompts, and text still arriving show headings, lists, task lists, tables, emphasis, links and fenced code the way a terminal would, and a reply looks the same while it streams as after it lands. Code blocks show their language and have a Copy button. Message text is treated as untrusted: raw HTML is dropped, links open in a new tab and only for web and mail addresses, and images appear as links rather than being loaded, so nothing in a message makes your browser fetch anything. Tool output stays verbatim, and syntax highlighting is still to come.

FIX: Long messages are no longer cut off. Replies, prompts and tool output past about 4000 characters used to end mid-sentence with an ellipsis, and Copy on a code block in them copied only what was shown. They are now kept and shown whole. Long code blocks open at their first 40 lines with a "Show all" button, and Copy always takes the whole block. Messages recorded before this fix stay as they were recorded.

FEATURE: Claude conversations run in the permission mode you choose, as in the terminal: default, auto (a classifier approves routine calls and only the rest is asked), accept edits, or plan. Pick it when launching. Change it from the conversation header while it runs; the change applies from the next tool call, shows in the history, and leaves any waiting approval in place. The choice sticks across release and resume, and a terminal visit never changes it. With no choice, Roundhouse uses the manual default mode, unless your Claude settings name a default mode, which is then inherited and marked as such. Approvals that still arrive in auto mode say the classifier could not decide them. Bypass modes are never offered.

FIX: When Claude refuses a permission mode switch, the conversation's stored choice now goes back to what it was before, including no choice at all, so a conversation that inherited its mode from your settings keeps inheriting. Roundhouse also reads your Claude settings the way Claude does for a checkout below its repository root: a default mode in the repository root's `settings.local.json` is inherited, the root's shared `settings.json` is not, and `auto` or bypass named in a project file is ignored, as Claude ignores it. Two error messages about permission modes now quote the names they mention.

CHANGE: A stopped Claude conversation's permission mode can be set from its header ahead of the next prompt, for example to auto after a restart. The choice is stored, shown as "next launch: X", and passed when the conversation next starts. The control shows for every Claude conversation except one whose supervision was lost.
