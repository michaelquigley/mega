# CHANGELOG

## Unreleased

FEATURE: `roundhouse` serves a localhost workspace on `127.0.0.1:8470` where projects are registered from existing checkouts, listed, renamed, and removed without touching the checkout. The list survives a restart, a change reaches the disk before any browser is shown it, a second instance on the same port or the same data directory refuses to start, and a project whose checkout Claude has not been trusted in shows a notice rather than having its trust flag set on the operator's behalf.

FEATURE: Claude Code conversations run inside a project: launch one with an opening prompt, reply, answer its approvals and questions from any open browser (the first answer wins and a late one is refused), interrupt it, release it to continue in a terminal with the exact `claude --resume` command shown, and resume it to pick up what happened there. Native permissions are inherited, never relaxed. A conversation always resumes its own session by id, and history from the terminal is added without repeating what is already shown. After a service restart, a conversation whose runtime was not seen to stop is marked as lost supervision until it is deliberately resumed, and any request that was pending is shown as lost rather than answerable.

FEATURE: Codex conversations run alongside Claude ones. Each gets its own private Codex server and inherits your approval policy and sandbox. Approvals and Codex's questions arrive as cards, and an answer to a question goes straight into the turn that is waiting for it. Release shows the exact `codex resume` command, and if a command Codex started is still running after release, the conversation says so with its process ids instead of claiming a clean stop.

FEATURE: Sessions started outside Roundhouse can be adopted. Pick a Claude or Codex session stored for the project's checkout from a list of those no conversation holds yet, and its history comes in with it; the first prompt continues that exact session.

CHANGE: Messages imported from a harness's own history are labeled as from outside Roundhouse rather than from the terminal, since adopted history can come from anywhere.

FEATURE: The workspace shows which conversations need you. A list at the top of the sidebar holds every conversation with a pending question or approval, then every one with unread output from a finished turn, each in the order it started waiting; Ctrl+/, or a bare n outside a text field, walks it. Every conversation in the project tree carries a mark for what it is doing: waiting for an answer, unread, working, ended in an error, idle, or uncertain after a restart. Opening a conversation marks what is on screen as read but never answers or hides a request. Releasing a conversation, restarting the service, or picking up a terminal visit does not make anything unread on its own.

FEATURE: A conversation can be removed from the workspace from its header, once its runtime is released. The confirm says what stays: the checkout and the agent's own session, which can be adopted again from the project. What goes is Roundhouse's own history and reading position for it. If the conversation was open, its project opens in its place, in every browser. Removing a project now works the same way for all its conversations: it waits until none of them has a runtime, including one whose supervision was lost in a restart, and it deletes Roundhouse's history and reading positions for them instead of leaving them on disk.

CHANGE: A conversation opens at its latest activity, with any waiting question or approval in view, instead of at the top of its history, and never keeps the scroll position of the conversation shown before. New output is followed only while you are at the bottom; if you have scrolled up to re-read, the view stays put and a "Newer activity below" button takes you back.

FEATURE: Conversations render markdown. Replies, your own prompts, and text still arriving show headings, lists, task lists, tables, emphasis, links and fenced code the way a terminal would, and a reply looks the same while it streams as after it lands. Code blocks show their language and have a Copy button. Message text is treated as untrusted: raw HTML is dropped, links open in a new tab and only for web and mail addresses, and images appear as links rather than being loaded, so nothing in a message makes your browser fetch anything. Tool output stays verbatim, and syntax highlighting is still to come.

FIX: Long messages are no longer cut off. Replies, prompts and tool output past about 4000 characters used to end mid-sentence with an ellipsis, and Copy on a code block in them copied only what was shown. They are now kept and shown whole. Long code blocks open at their first 40 lines with a "Show all" button, and Copy always takes the whole block. Messages recorded before this fix stay as they were recorded.

FEATURE: Claude conversations run in the permission mode you choose, as in the terminal: default, auto (a classifier approves routine calls and only the rest is asked), accept edits, or plan. Pick it when launching. Change it from the conversation header while it runs; the change applies from the next tool call, shows in the history, and leaves any waiting approval in place. The choice sticks across release and resume, and a terminal visit never changes it. With no choice, Roundhouse uses the manual default mode, unless your Claude settings name a default mode, which is then inherited and marked as such. Approvals that still arrive in auto mode say the classifier could not decide them. Bypass modes are never offered.

FIX: When Claude refuses a permission mode switch, the conversation's stored choice now goes back to what it was before, including no choice at all, so a conversation that inherited its mode from your settings keeps inheriting. Roundhouse also reads your Claude settings the way Claude does for a checkout below its repository root: a default mode in the repository root's `settings.local.json` is inherited, the root's shared `settings.json` is not, and `auto` or bypass named in a project file is ignored, as Claude ignores it. Two error messages about permission modes now quote the names they mention.

CHANGE: A stopped Claude conversation's permission mode can be set from its header ahead of the next prompt, for example to auto after a restart. The choice is stored, shown as "next launch: X", and passed when the conversation next starts. The control shows for every Claude conversation except one whose supervision was lost.

FIX: Codex conversations can use MCP tools. Codex asks before running an MCP tool, and that question used to go unanswered, so the turn hung until interrupted (which blocked, for one, running a terminus review from a Codex conversation). It now arrives as an approval card naming the server and the tool, with what the tool does and the parameters it would be called with: Allow runs it, Deny stops it, and where Codex offers it, "Allow this tool for the session" stops it asking again for that tool in that conversation. Roundhouse never chooses "always", which would change your Codex configuration. A form an MCP server asks you to fill in (choices, text, numbers, yes or no) appears as a question card. Kinds Roundhouse cannot answer yet are recorded saying what was asked, and interrupting still gets you out.

CHANGE: Roundhouse is set in the house faces. Messages, headings, buttons and other prose are in Source Serif 4 at a slightly larger size with more room between lines. Labels are in Nordwand Mono: the conversation's facts, statuses, tool lines, request parameters, timestamps and code. Both faces are built into the binary, so the page still fetches nothing from outside your machine. The serif carries Latin only, and other scripts fall back to Georgia. The conversation column is also wider, up to 960px instead of 860px, so code and tables have more room.

FIX: A subagent's report no longer shows up as a message from you. When Roundhouse read a Claude conversation's history after a restart or a terminal visit, a report a subagent handed back appeared as "You, outside Roundhouse". Those messages are now recorded as Claude's own and shown only with native events. Prompts you typed ahead while a turn was running still show as yours. Messages already recorded stay as they are.

CHANGE: Text in the conversation pane is 10% larger: messages, the header, status lines, code and request cards. The sidebar and dialogs keep their size.

FEATURE: Conversations run on the model and effort level you choose, for Claude and Codex alike. The launch dialog lists the harness's own models and, for the one you pick, only the effort levels it takes; it starts at inherit, which applies your own settings, and says what inherit means here (for Claude, what your settings name, such as "settings name opus"). The choice is kept and passed again at every launch. For Codex, inherit sends your config's current model and effort with every turn, so a conversation set back to inherit returns to your config. A running conversation can change both from its header: Claude switches from its next response, Codex from your next prompt, and with no runtime the change waits for the next launch. The header shows the model as the harness reports it, the effort as Codex reports it or, for Claude, which never reports it, the level asked for, marked "(requested)", and "next prompt: …" for a change not yet in effect.

CHANGE: You can see at a glance what is working. A working conversation's mark is a turning arc, and the marks are a little larger. Next to the name, the tree and the needs-you list show how long the turn has run (45s, 4m, 1h 12m). Each project carries one mark for its most urgent conversation, with a waiting request, lost supervision, an error or unread output ranked above working, and a title saying how many ("2 working"). Above the reply box, a line says what is happening now and for how long: the command running, "Writing" while text arrives, starting or stopping. It says "Waiting for your approval" or "Waiting for your answer" when you are needed. A command in flight in the history shows the same small spinner. Nothing moves that is not live: with reduced motion set, or while the page has lost its connection and shows only what it last knew, the marks hold still and the times stop.

CHANGE: A conversation reads as blocks. The agent's replies sit on a slightly different tone from the page, as your prompts already did on theirs, with code inside a reply set into it. A run of tool calls between two replies becomes one quiet, indented passage with a hairline down its side. Blocks have more room between them. A reply still arriving already wears its block, so nothing jumps when it lands. A conversation waiting on your answer now shows, beside its name, how long the request has waited rather than how long the turn has run. The reply box no longer says "Working" twice.

CHANGE: The bottom of a conversation is now where you work. A pending approval or question docks just above the reply box, always in view, while the history keeps a one-line record of it. The reply box rests at one line and opens when you use the panel, to a height you can drag and that every conversation remembers, and your draft is never hidden. A control bar under it holds Send, Interrupt, the permission mode, model and effort, and a menu for Release, Resume, Name and label, Remove and the native events toggle. The header above is now just what the conversation is and what the harness reports. Release asks first, and its confirmation shows the exact command to resume in a terminal, with a copy control, and the rule to close that terminal before coming back. Buttons are icons wherever their meaning is conventional, each named on hover; Allow and Deny keep their words.

CHANGE: The side panel can be arranged. Projects are listed by name, ignoring case, and a star keeps your favourites in their own group at the top; a star is part of the workspace, so it is the same in every browser. A project folds away its conversations and still shows its most urgent mark, and opening a conversation from the needs-you list or the next-waiting shortcut unfolds it. Drag the panel's edge to make it wider or narrower, or collapse it to a thin rail. The rail still shows how many conversations need you, one mark per project (a turning arc while one works), and clicking a mark opens that project. Project names are bold throughout, and a project's conversations are indented beneath its name. Width, the collapsed rail and folded projects are remembered in this browser.

CHANGE: Every prompt and reply can be copied with one click, as markdown (exactly what was written) or as plain text (what you see, without the markup: a link keeps its address in parentheses, a table becomes tab-separated rows). The two controls appear when you point at a message, and turn into a check for a moment once copied. An expanded tool result has a copy control for its whole output. A long code block you expand while a reply is arriving stays expanded once it lands. The adopt dialog's radio buttons sit beside their sessions. A running Codex conversation can go back to inherit, taking your config's model and effort from the next prompt.
