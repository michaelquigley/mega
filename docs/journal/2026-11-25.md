## A turn is what the harness says it is (implementation agent)

Piece 4, `a-turn-is-inferred-from-a-message`, was built from the card alone, begun late on 2026-11-24. It is in the working tree for Michael's trial, not committed.

**The check came first.** `probes/turn-markers/check.mjs` reads the recorded probe logs, by frame type and turn id only, and its README holds the result. Every turn in them has the harness's own start before its end: Claude 89, Codex 54, pi 62. Every start without an end is a probe that killed, suspended or timed out mid-turn. Two things it turned up:

- **pi sends `agent_start` again for each retry inside one run,** with one `agent_settled` at its end: twelve in `rt1-managed`, matching its twelve `auto_retry_start`s. So a start while a turn is open changes nothing.
- **`hold-ws` logs every Codex frame twice,** because it has two clients. That is the log's doing, not Codex's.

Michael's own logs were read the same way, by kind and status: 17 Claude conversations, 502 `system/init`s and 501 ended turns. The one still open was this session's own turn in flight. Nothing stopped the work.

**The shape.**

- **`Sink.TurnStarted()` is the only thing that opens a turn.** It is a signal in memory, and nothing is recorded for it. It folds in what `beginTurnLocked` did, and that function is gone. A start while a turn is open changes nothing.
  - Claude declares it at every `system/init`, the first included.
  - Codex declares it once per turn, in `namedLocked`: by `turn/started` or by the reply to `turn/start`, whichever comes first, and never for a turn whose `turn/completed` has been read. `r.mu` is held across the sink call, so the reader cannot report the turn's end first.
  - pi declares it at `agent_start`.
- **`send` records the prompt and opens nothing.** The rule that a message opens a turn is gone from `sink.Event`.
- **The prompt rows are records only.** A refused prompt's row closes nothing in memory and carries no turn record. So does a prompt pi handles. After finding 1 below, pi's `Prompt` returns `*harness.Handled`, and the service records that row itself, as it records a refusal. The only turn end that reaches the service through the sink is now the harness's own.
- **Deleted outright:** `model.Event.AfterTurn`; the Codex adapter's two writes of it; its reader in the turn's settling; and on the page, `after_turn` in `types.ts`, `mergeEvents`, `toolInFlight` and the tool row's spinner in `EventList.tsx`.
- **The fakes.**
  - `harnesstest.Runtime.Prompt` declares a start unless `HoldStarts` was set, and `StartTurn` declares one with no prompt.
  - The fake Claude shim no longer sends `system/init` at a prompted launch. Claude does not, and here it would have opened a turn before the prompt.
  - The fake Codex's `late-search` now ends its turn before reporting the search. `late-message` became `late-stream`, which streams only.

**What changed in behaviour that the card did not spell out:**

- **A turn's `asked` is taken when the harness starts the turn,** no longer when the prompt is sent.
- **`turn_started_at` is the start's time,** not the prompt's.
- **Some states now count as idle.** In the moment before the start, a release sends no interrupt, and the shutdown gate counts the conversation idle. A runtime that exits there records a plain stop, not "exited during a turn".
- **`codex-interrupt-while-a-turn-is-starting` holds as built.** Before Codex names the turn, the page offers no Interrupt, since `InputPanel` shows it only with a turn open or a request pending. An interrupt sent through the API then marks nothing under way, and the Codex adapter sends nothing. The card's state is left for the planning agent.
