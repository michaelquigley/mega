## Design session (combined design/planning agent)

- Environment-authoritative truth: each environment service owns its projects' registry, roster, event history, pending set, reading state, and suspension state. The central app holds login, enrollment, and a last-seen cache only. Browsers never write workspace state directly.
- "Environment" replaces "host" as the registered unit. Identity is per environment, not per machine, so per-project containers on `fortyfive`/`twentytwo` remain possible later. The service runs inside the environment; registries sit on durable storage the environment owns (a volume, for containers).
- Runtime mode is per conversation: long-lived default, per-turn opt-in, per-harness default plus a global switch. Long-lived conversations need an explicit release before terminal handoff; per-turn ones do not.
- Mercurius and terminus keep session state in memory and run rounds inside the MCP server process (`internal/broker/broker.go` `sessions` map; `status.json` is already durable). Making them restartable is follow-on work in those repos that unlocks per-turn mode for broker-driving conversations; not a Roundhouse prerequisite.
- Local inference is a re-entry briefing for Michael's own context across projects, generated by the environment service at turn end. Later stage; stage one records turn boundaries and event history for it.
- Stack: Go with `df/dl` and `df/dd` for central app and environment service; TypeScript confined to a policy-free Claude Agent SDK shim speaking JSONL on stdio (the probes' relay owner mode is the shape).

## Implementation, stage 1 (implementation agent)

Built the skeleton per the work order: module, Makefile, cobra, config, XDG directories, registry, event log, model, HTTP server with embedded UI, WebSocket fan-out with heartbeat, project registration end to end, trust notice. Harness adapters start in stage 2.

- Mechanism choices the work order left open: `gorilla/websocket` (what scry and astrometrics use). `Event.Raw` and `Request.Payload` are `any` with `dd:",+opaque,+nullable,+omitempty"` rather than `json.RawMessage`, because `dd` is the binding substrate and carries opaque values natively. JSON numbers inside them decode to `float64`.
- Added beyond the listed stream frames: `{workspace_changed: true}` (two browsers need project changes, and no conversation exists to hang them on) and `{heartbeat}` (pings are invisible to page script).
- Added beyond the work order: a `Host` and `Origin` guard in front of everything. The loopback bind does not stop a web page in the same browser from reaching `127.0.0.1`, and this service will launch agents and answer approvals with no login. It is about ten lines. `ui/vite.config.ts` sets the proxied `Origin` to match.
- Trust notice is recomputed on read, not only at load, so a terminal visit clears it without a restart. It parses `~/.claude.json` once per project per workspace read; fine at this size, worth a cache if the workspace read ever shows up.
- Trust key read out of the 2.1.318 binary: the check that gates permission rules is `projects[gitRoot ?? realpath].hasTrustDialogAccepted`. There is a separate ancestor-walking check for other purposes, so a trusted parent directory outside a repository does not count here.
- `Project.Untrusted` is `dd:"-"` so it can never reach the registry; `server.projectView` carries it on the wire.
- `registry.Update` applies to a copy and swaps only after the file is durable, so a failed write cannot leave memory ahead of disk.
