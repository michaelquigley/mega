### What was built

- Shim: `run` takes `--model` and `--effort`, each omitted when unchosen. The `set_model` and `set_effort` frames call `setModel` and `applyFlagSettings` and reply `model_set` or `effort_set`. The `models` command starts an idle session and prints `{version, models}`.
- Seam:
  - `Spec.Model` and `Spec.Effort`;
  - `Harness.Models(cwd)` returns a catalog, and `Harness.Inherited(cwd)` the model and effort inherit means;
  - `Runtime.SetModel(model, effort) (deferred, err)`;
  - `model_changed` runtime events carry `Facts.Model`, and for Codex `Facts.Effort`.
- Claude adapter:
  - `SetModel` sends only what differs and waits for each reply, timing out to `ErrSettingUnconfirmed`;
  - a later `system/init` with another model is a `model_changed`;
  - `Inherited` walks the same settings layers as the permission mode, reading top-level `model` and `effortLevel`;
  - the catalog's `default` entry is marked `is_default`.
- Codex adapter:
  - `model` goes on `thread/start` and `thread/resume`;
  - every `turn/start` (prompt and answer) is built by `turnStart()`, carrying the stored model and effort;
  - `SetModel` stores the choice and returns deferred;
  - `thread/settings/updated` that differs from the last report is a `model_changed`;
  - `Models` uses a short-lived app-server, skips hidden models, and takes the version from the `initialize` user agent;
  - `Inherited` uses `config/read`.
- Service (`internal/service/model.go`):
  - `LaunchChoice{PermissionMode, Model, Effort}` replaces the mode argument of `StartConversation`;
  - the conversation record gains `model` and `effort`;
  - catalogs are cached per harness for the service's life, and what inherit means is read on every ask;
  - choices are checked against a cached catalog, and by form otherwise, since they reach a command line;
  - `SetModel` follows `SetPermissionMode`: stored with no runtime; otherwise written first, then asked, giving `confirmed`, `next_prompt` (Codex), `refused` (the choice is restored) or `unconfirmed`, under the shared one-change guard;
  - `harnessModelChanged` is the one writer of the live model and effort.
- Server: `GET /api/projects/{id}/models?harness=`, `POST /api/conversations/{id}/model`, `model` and `effort` on the launch body, and on the conversation `effort`, `model_choice`, `effort_choice`, `model_next` and `effort_next`.
- UI:

## Batch: a failed load never renders as an empty workspace (implementation agent)

Built to `docs/future/roadmap/a-failed-load-never-renders-as-an-empty-workspace.md`, under `honest-runtime-state`: the page shows what it knows, and says when it does not know. The card's state is left as Michael set it.

### What was built

- `App` derives `knowledge` (`stream.ts`'s `Knowledge`) from `workspace === null`, `loadError` and the stream state:
  - `connecting` until a read or the stream fails;
  - `unreachable` after that, while the page has never read the workspace;
  - otherwise `current`, or `stale` when the stream is down or unsynced.
- The main column renders `Unknown` (the address from `window.location.host`, "keeps trying", the last error) instead of the empty-state placeholder while never loaded. The "workspace could not be read" banner shows only once the page has had a workspace.
- The side panel takes `knowledge`:
  - needs-you and projects each show a `.unknown-line`, never "Nothing waiting." or "No projects yet.";
  - Register is disabled with a label saying it waits for the service;
  - the footer reads "Unreachable, retrying".
- The rail's count reads `?` (`.rail-count.unknown`, dashed) with an aria-label saying not known. The dot is `stream-disconnected` when unreachable, or an empty ring while connecting.
- Retry: a workspace read that fails while the stream is connected is retried by an effect: 1 s, then doubling to at most 8 s, reset on success. Before this, a first read failing with a 500 while the stream was up was never retried: nothing asks again until a `workspace_changed` frame.

### Gotchas

- The page is served by the service, so "load the page with no service" needed the check to serve `ui/dist` itself through Playwright routing, with `/api` and the stream left to the real port.
- Chrome then blocks the stream with `ERR_BLOCKED_BY_LOCAL_NETWORK_ACCESS_CHECKS`: a routed document has no address and counts as public. The check launches its browser with `--disable-features=LocalNetworkAccessChecks`. This is a harness artefact; the real page, served from loopback, is not affected.
- A browser context's `localStorage` is its own, so the dark page shares neither folds nor the collapsed rail with the light one.
