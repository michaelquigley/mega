## Decisions

- Drive Claude through the Agent SDK (version-matched to the CLI) rather than hand-rolled `stream-json`; the SDK's `sdk.d.ts` was used as the protocol reference instead of memory.
- Pass `permissionMode: 'default'` explicitly so permission requests actually reach the host; the SDK otherwise picks the CLI's starting mode, which can be `auto`.
- Record the background-session daemon's sockets (`/tmp/cc-daemon-1000/...`, `/run/user/1000/cc-socks/*.sock`) as observations only. They are undocumented internals; no probe connects to them.
- Codex and pi round trips were delegated to two forked agents with the same rules; their notes land in `probes/codex/NOTES.md` and `probes/pi/NOTES.md` and are merged into the report by the lead.

## Blockers and notes

- Bare `sleep N` is blocked by the installed Bash tool as a "standalone sleep"; the model then backgrounds it. Long-running fixtures must use something else (a Python sleep worked).
- The `claude --bg` help text says "(API key users only)" next to the resume clause; starting a background session worked under the operator's subscription login, so the restriction, if any, applies elsewhere.
- Michael's `claude --resume aa205d40...` terminal was still running after the split test; closing it is on the next terminal request.
- Browser-disconnect and central-restart simulations were not run for Claude today; the SDK host is the only client, and a loopback shim would be needed to make the test meaningful. The protocol has an initialize re-send that redelivers pending `can_use_tool` requests, untested.
