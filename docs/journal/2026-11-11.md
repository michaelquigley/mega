### What was built

- `internal/service/checkout.go`:
  - `checkoutProblem(path)` returns `does not exist`, `not a directory` or `not readable`, or empty. It uses `os.Stat`, then `syscall.Access(R|X)`, since a harness lists and enters the directory.
  - `checkoutRefusal` gives the code `checkout_missing` (409) and the message "the checkout is missing: '<path>' (<reason>)".
  - `checkoutLocked` also calls `s.changed()`. A directory moving announces nothing, so the refusal is when the service learns of it, and every page reads the notice at once.
- `applyTrust` sets `model.Project.CheckoutMissing` (`dd:"-"`, never stored) on every read, beside `Untrusted`. The wire field is `checkout_missing`, omitted when empty.
- Refused, after the gate's check where there is one: Prompt (running or stopped) and Start (both through `conversationCheckoutLocked`), StartConversation, and Adopt. Adopt checks before discovery, so the refusal is not hidden behind "not an unadopted session". Discover and Paths return empty lists. Resume, mode and model changes, reads, rename, star and removal are untouched; Resume was not on the card.
- UI:
  - `checkout.ts` `missingReason`;
  - `heldBy ?? missingReason(project)`, so a pending shutdown's reason comes first;
  - a `role="alert"` notice on the project page;
  - an `error_outline` mark on the tree row and a red ring on the rail mark, both titled with the reason;
  - the trust notice hidden while the checkout is missing, on both pages.
